# Completion audit: 0.4.1

The previous 0.4.0 closure omitted a runnable generated documentary comparison,
session-scoped research recall and real heterogeneous documentary examples. A further
defect allowed changed index columns to silently remove results without failing verify.

The defect was reproduced with the installed 0.4.0 wheel on a disposable database:
changing H6's indexed status produced zero matching records while verify returned
`integrity=verified`. 0.4.1 verifies rows and memberships against preserved publications
before filtering; missing links and altered domain/source/type/state/revision fail closed.
Rebuild restores them without changing the originals or receipts.

Research history uses existing user/project/session selection plus collection scope.
Queries are replayed; historical explanations are separately marked and their publication
dependencies authorized before reading cached answer bytes. Read revocation during
generation suppresses both the explanation and now-inadmissible facts; generation-only
revocation continues to preserve readable deterministic facts. Duplicate JSON keys are
rejected, and the existing structured provider method is used when supported.

The comparison now has executable documentary and structured generation arms with the
same provider, exact-ID filters, evidence/response byte bounds and per-arm call ceilings.
Its no-provider run stays explicit. A second protocol uses two source groups outside
Crypto development: Stocks readiness and Brasileirão market comparison. These remain
documentary recovery tests, not independent scientific trials or economic validation.

Observed local checks: 350 passed, one Windows symlink privilege skip; JavaScript
syntax and changed Python lint passed. Installed 0.4.1 was exercised outside the
checkout on Python 3.12.14. The running browser reopened H6 history after a server restart,
replayed the query and exposed the preserved charter. It also displayed all four real
heterogeneous documentary rows and exact Brasileirão support bytes.

Crypto's main CLI research-export branch was additionally executed on its pinned real
reports, with pipeline import forbidden. Its publication ID matched the earlier export.
The first verification helper failed on Windows' default text encoding before dispatch;
explicit UTF-8 fixed the helper. No scientific source was changed.

No Stocks/Brasileirão runtime, test suite, protected evaluator, database, live source
collection or economic operation was executed. Their existing current instructions and
freeze restrictions were read. New reference clones were moved into each domain's
required root after its location rule was discovered. The Brasileirão clone needed Git's
repository-local long-path setting and an index restore after Windows checkout failed.

The local Ollama HTTP probe failed; no executable in PATH, matching process, installation
in inspected standard program locations or manifests in the standard user model directory
were found. This is scoped availability evidence, not an exhaustive disk inventory.
No model was downloaded and no permanent service installed. Real inference and human
utility scoring remain unverified; both deterministic comparisons tied their documentary
baseline (5/5 development, 3/3 evaluation questions across two new source groups).

Implementation is complete within the documented L0 profile; full empirical validation
is partial because real provider execution and human utility evaluation are unavailable.
The interface keeps generation optional. No push, merge, release or scheduler was used.
